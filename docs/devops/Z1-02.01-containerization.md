# Z1-02.01 – Frontend containerization

Goal: build a production image for the React + TypeScript + Vite frontend using a
multi-stage Dockerfile on Docker Hardened Images (DHI), and compare it with a naive
single-stage image.

## Files

| File | Purpose |
|------|---------|
| `frontend/Dockerfile` | Multi-stage build: `deps` → `dev` → `build` → `production` (default target) |
| `frontend/Caddyfile` | Static SPA server configuration for the production stage (ADR-008) |
| `frontend/.dockerignore` | Keeps `node_modules`, `.git`, `.env*`, `dist`, Dockerfiles, IDE files out of the context |
| `frontend/Dockerfile.naive` | Single-stage image, **for comparison only** |

## Base images

Tags were checked against `dhi.io` (after `docker login dhi.io`) rather than guessed.

| Stage | Image | Resolved (2026-09-29) |
|-------|-------|-----------------------|
| `deps`, `dev`, `build` | `dhi.io/node:24-alpine3.23-dev` | Node 24.21.0, index digest `sha256:b8099f4a…73f1` |
| `production` | `dhi.io/caddy:2.11-debian13` | Caddy 2.11, index digest `sha256:1b40b4f4…ddcc` |

- The `-dev` Node variant is used only in build stages because it contains npm and a shell,
  which `npm ci` and `npm run build` need. None of it reaches the final image.
- DHI publishes Caddy only on `debian13` (`caddy:2-alpine3.x` tags do not exist).
- The production stage uses Caddy instead of a Node runtime, as decided in ADR-008: the SPA is a
  static bundle and needs no Node process at runtime.

## Production image properties

- Multi-stage build: only `dist/` (≈250 kB) and the `Caddyfile` are added on top of the DHI Caddy base.
- Dependencies are installed with `npm ci` using the lockfile, with a BuildKit cache mount for the npm cache.
- `npm run build` runs the TypeScript type check before `vite build`, so a type error fails the image build.
- Runs as non-root: `USER 65532:65532` (DHI `nonroot`), listening on `:8080`, since a non-root user cannot bind `:80`.
- No shell in the runtime image (`docker exec … sh` fails with `executable file not found`).
- Caddy serves `index.html` for unknown paths (SPA fallback). `/assets/*` (content-hashed) are sent with
  `Cache-Control: immutable`, `index.html` with `no-cache`, and responses are compressed with zstd/gzip.
- Out of scope here, planned for the Build phase (ADR-008): TLS and the `/api` + `/ws` reverse proxy to the backend.

## Commands

```bash
cd frontend
docker build -t thousand-frontend:prod .
docker build -f Dockerfile.naive -t thousand-frontend:naive .

docker run -d --name fe-prod  -p 18080:8080 thousand-frontend:prod
docker run -d --name fe-naive -p 14173:4173 thousand-frontend:naive
```

## Verification (`docker run`)

```text
$ curl -s -o /dev/null -w "%{http_code} %{content_type}\n" localhost:18080/
200 text/html; charset=utf-8
$ curl -s -o /dev/null -w "%{http_code}\n" localhost:18080/lobby/abc      # SPA fallback
200
$ curl -sI localhost:18080/assets/index-<hash>.js
HTTP/1.1 200 OK
Cache-Control: public, max-age=31536000, immutable
Content-Type: text/javascript; charset=utf-8
$ curl -sI localhost:18080/ | grep -i cache-control
Cache-Control: no-cache

$ docker top fe-prod
UID     PID    ...  CMD
65532   59594  ...  /usr/local/bin/caddy run --config /etc/caddy/Caddyfile

$ docker exec fe-prod sh -c true
OCI runtime exec failed: ... exec: "sh": executable file not found in $PATH

$ curl -s -o /dev/null -w "%{http_code}\n" localhost:14173/               # naive
200
$ docker exec fe-naive id
uid=0(root) gid=0(root) groups=0(root)
```

The development stage is still used by `compose.override.yaml` (`target: dev`).
`docker compose build frontend` succeeds and the container reports `node --version` → `v24.21.0`.

## Size comparison

```text
$ docker image ls thousand-frontend
IMAGE                     ID             DISK USAGE   CONTENT SIZE
thousand-frontend:naive   7f0b9aa040f8       1.89GB          467MB
thousand-frontend:prod    b540162853d4       80.6MB         16.7MB

$ docker image inspect thousand-frontend:naive --format '{{.Size}}'
466587555
$ docker image inspect thousand-frontend:prod --format '{{.Size}}'
16738378
```

| Metric | Naive (single-stage, `node:24`) | Production (multi-stage, DHI) | Difference |
|--------|--------------------------------:|------------------------------:|-----------:|
| Content size (compressed, `{{.Size}}`) | 466.6 MB | 16.7 MB | −449.8 MB (−96.4%, ~28× smaller) |
| Disk usage (unpacked + content) | 1.89 GB | 80.6 MB | −1.81 GB (−95.7%, ~23× smaller) |
| Runtime user | `root` | `65532` (nonroot) | |
| Shell / package manager in image | yes / npm, apt | no / no | |
| Ships dev dependencies and sources | yes | no (only `dist/`) | |

Measured on Docker Desktop with the containerd image store (linux/arm64). `CONTENT SIZE` is the
compressed size of the image layers, as pulled from a registry. `DISK USAGE` also includes the unpacked snapshot.

### Why the naive image is so much larger

- It is based on the full `node:24` image (Debian with build toolchain, Python, git and more).
- `node_modules` with all dev dependencies (TypeScript, ESLint, Vitest, jsdom and more), the sources
  and the npm cache stay in the final image.
- It serves the bundle with `vite preview`, which is a development tool, and runs as root.
